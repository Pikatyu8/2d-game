# 2D Action Platformer & AI Visual Graph Editor

Экспериментальный проект двухмерного экшен-платформера с акцентом на проработанное поведение противников. Проект разделен на два ключевых модуля: **игровой движок с редактором уровней** (реализован на Pygame) и **внешний графический редактор ИИ** (реализован на Dear PyGui), которые синхронизируются друг с другом в реальном времени.

---

## Основные особенности проекта

*   **Игровая механика (Pygame):**
    *   Упрощенная двухмерная физика с обработкой коллизий и платформ.
    *   Система ближнего боя с расчетом векторов отдачи (Knockback) при попаданиях.
    *   **Механика парирования (Parry):** Игрок может парировать атаки противников и отражать летящие снаряды обратно во врагов с автонаведением. Успешное парирование временно увеличивает урон по врагу за счет накопленного счетчика (`Parry Damage`), останавливает время на несколько кадров (Hitstop) и проигрывает процедурный звуковой эффект.
*   **Встроенный редактор уровней:**
    *   Позволяет налету переключаться между игровым процессом, редактированием уровня и настройкой базовых параметров шаблонов (`Gameplay` / `Level Editor` / `Enemy Editor`).
    *   Привязка к сетке (Grid Snap), создание и перемещение платформ, размещение спавнов игрока и противников.
*   **Синхронизация в реальном времени:**
    *   Редакторы общаются через файл состояния `.editor_selection.json` и файлы конфигураций в папке `enemies/`. Выделение узла в визуальном редакторе Dear PyGui мгновенно фокусирует камеру и открывает нужную вкладку инспектора в окне Pygame.

## Визуальный редактор ИИ (Node Editor)

Графический редактор позволяет конструировать дерево решений и боевые сценарии противников без написания кода. Редактор автоматически подтягивает шаблоны коллизий из `config.py` и сохраняет изменения в JSON-пресеты противников.

### Ключевые узлы (Nodes)

1.  **Root (Корневой узел):** Содержит общие параметры противника (HP, размеры тела, тип передвижения — наземный или летающий, скорость патрулирования) и зону обнаружения игрока (Vision Trigger).
2.  **Flow (Поток поведения):** Высокоуровневая логика выбора тактики. Задает кулдауны, вероятность выбора ветки (`chance`), зону удержания триггера (`hold_time`) и лимит повторений перед сбросом.
3.  **Sequence (Последовательность):** Хронологическая цепочка действий, запускаемая при соблюдении условий триггера.
4.  **Attack (Атака) и Hitbox (Хитбокс):** Конфигурация боевых приемов. К ноде атаки можно прикрепить цепочку хитбоксов, настроив для каждого кадр задержки (`delay`), длительность, наносимый урон и параметры отдачи игрока (направление и силу как при обычном ударе, так и при парировании).
5.  **Movement (Движение) и Phase (Фаза):** Позволяет настраивать сложное маневрирование противников (рывки к игроку, отскоки назад, телепортацию сквозь стены). Направление движения может плавно затухать или нарастать благодаря кривым скорости (`Velocity Curves`).
6.  **Projectile (Снаряд):** Настройка дальних атак противника — скорость снаряда, влияние гравитации, поддержка активного автонаведения на игрока в воздухе (`homing`) и частота стрельбы.

### Дополнительный инструментарий редактора

*   **Interactive Preview Panel (Панель предпросмотра):** Окно симуляции физического тела противника. Позволяет прямо мышкой на холсте перетаскивать, растягивать и вращать зоны видимости, хитбоксы атак и триггерные зоны, мгновенно обновляя числовые параметры в инспекторе.
*   **Sequence Timeline (Шкала времени):** Визуализирует выбранную последовательность действий на шкале кадров, разграничивая время подготовки атаки (замах/windup) и фазы активного урона.

## Новая механика: seq/flow order (Узел порядка)

Нода **`seq/flow order`** представляет собой узел упорядочивания логики противника. Она позволяет связать несколько последовательностей действий (`Sequence`) или тактических решений (`Flow`) в единую приоритетную очередь.

### Как это влияет на геймплей и поведение ИИ

До добавления этой механики ИИ выбирал действия на основе простых триггеров расстояния и случайной вероятности. Это приводило к тому, что противники вели себя хаотично или циклично спамили один и тот же прием. 

Внедрение узла порядка решает эту проблему и меняет игровой процесс следующим образом:

1.  **Многосвязность и разветвление комбо-цепочек:**
    Входы ноды `seq/flow order` поддерживают **неограниченное количество входящих связей** от разных Sequence и Flow. Это позволяет одной и той же атаке или перемещению участвовать в нескольких тактических цепочках (например, условный "Удар мечом" может быть шагом №1 в «Агрессивном комбо» и одновременно шагом №3 в «Контратакующем комбо после отскока»).
2.  **Фазированный бой и длинные серии атак:**
    С помощью шагов (Step 1, Step 2, Step 3...) можно выстраивать строгую очередность приемов. Противник больше не прерывает логику на середине: он обязан завершить первый шаг цепочки (например, сблизиться рывком), прежде чем перейти ко второму (сделать замах) и третьему (выпустить снаряд). Для игрока это означает появление читаемых комбо-серий, ритм которых можно заучить для идеального проведения парирования.
3.  **Повышение вариативности и непредсказуемости ИИ:**
    Поскольку один шаг порядка может принимать сразу несколько связей, ИИ в процессе прохождения шага может совершить случайный выбор из пула привязанных к нему действий. Противник двигается по одной и той же цепочке порядка, но на Шаге 2 может либо провести быстрый выпад, либо сделать обманный маневр. Бой становится более динамичным и менее предсказуемым.

### Удобство отладки в редакторе

Для того чтобы разработчик не запутался в очередях выполнения, на специальных выходах `order:` у нод Sequence и Flow динамически генерируются плашки-кнопки вида **`[1]`**, **`[3]`**, показывающие, в каких шагах и каких узлах порядка участвует данное действие. 

При наведении курсора на такую плашку, соответствующая нода порядка на холсте **подсвечивается ярким бирюзовым цветом**, помогая визуально отследить логические связи в сложных деревьях поведения.

## Установка и запуск

### Требования
*   Python 3.11 или выше (тестировалось на Python 3.13)
*   Установленные библиотеки `pygame` и `dearpygui`

### Установка зависимостей
```bash
pip install pygame dearpygui
```

### Запуск проекта

1.  **Запуск игры и редактора уровней:**
    ```bash
    python main.py
    ```
    *Управление в режиме редактора уровня/противника:*
    *   `E` — Переключение режимов (`Gameplay` / `Level Editor` / `Enemy Editor`).
    *   `TAB` — Включение/выключение отладочной визуализации (отображает зоны видимости, хитбоксы и триггеры).
    *   `Колесо мыши` — Изменение масштаба камеры (Zoom).
    *   `Зажатие ЛКМ (в режиме Selection)` — Панорамирование камеры.
    *   `SHIFT + R` — Быстрая перезагрузка уровня.

2.  **Запуск визуального редактора ИИ (Node Editor):**
    Запускается автоматически кнопкой **`LAUNCH NODE EDITOR`** из панели свойств противника в Pygame, либо вручную:
    ```bash
    python editor/node_editor.py
    ```
    *Управление в нодовом редакторе:*
    *   `F11` / `ESC` — Переключение полноэкранного режима.
    *   `P` — Скрыть / показать интерактивное превью.
    *   `F` — Переключить фокус на панель предпросмотра.
    *   `ПКМ` — Панорамирование холста симуляции в превью.
